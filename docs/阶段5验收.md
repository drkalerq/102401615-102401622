# 第五阶段验收：复制、我的发布与状态更新

## 验证情况

Node.js 单元测试共 43 个通过、0 个失败：原 31 个，加我的发布与状态 8 个、剪贴板处理 4 个。脚本语法、HTML 引用及新增元素检查通过。

用户已反馈第四阶段 31 个单元测试在本人电脑正常运行。第五阶段浏览器交互仍待人工验证，不能以业务测试代替剪贴板、弹窗和浏览器刷新检查。

## Chrome 人工验收

1. 合并到原项目目录，打开同一个 index.html。此前发布的信息应继续存在（存储键不变）。
2. 发布一条寻物信息，在“我的”中找到它，应显示“待寻找”和“标记已找回”。
3. 点击标记，先选择取消，状态应不变。再次操作选择确认，应显示已找回，统计中的寻物中减少、已完成增加。
4. 返回首页、搜索和详情，确认该条状态一致；搜索勾选“仅看未完成”时，不应显示它。
5. 按 F5，确认已找回状态仍保留。
6. 再发布招领信息，进入我的，标记已归还并确认。首页、搜索及详情应显示已归还。
7. 在已完成分类中点击恢复进行中并确认，原寻物应恢复待寻找，原招领应恢复待认领。
8. 点击我的列表卡片查看详情，返回列表仍回到“我的”并保留状态筛选。
9. 查看一条详情、展开联系方式、点击复制；如出现成功提示，在记事本按 Ctrl+V 核对完整内容。
10. 若浏览器不允许自动复制，应出现失败提示及手动选中。按 Ctrl+C，再到记事本粘贴验证。

## 实现边界

- 没有后台登录，以本地字段标识自己发布的信息。
- 原型中编辑／删除将下一阶段补齐；本阶段只实现状态管理。
- 剪贴板成功只代表浏览器 API 接受写入，真实系统粘贴仍需人工核对。
- 存储读取失败时禁用发布及状态更新，避免覆盖旧记录。
