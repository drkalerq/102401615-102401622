# 第三阶段验收：发布与本地保存

## 本阶段实现

- 寻物／招领类型切换；五种类别选择。
- 名称、地点和联系方式必填，去除首尾空格。
- 文本长度限制和有效日期检查，逐项显示错误并聚焦错误输入。
- 未填写事件时间时使用发布时刻；列表按发布时间排序。
- 保存成功才更新首页、清空表单及显示成功提示；失败保留输入和列表。
- 发布成功后回到“全部”筛选，新信息显示在顶部。
- localStorage 保存与加载：版本、字段及编号检查，坏数据不自动覆盖。

Node.js 单元测试 21 个通过、0 个失败。覆盖首页 6 个用例、发布校验与创建 8 个用例、存储 7 个用例。另通过脚本语法和 HTML 本地引用路径检查。

## Chrome 人工验收

1. 打开根目录 index.html，进入发布页。不填必填项直接点发布，应出现错误提示且不新增信息。
2. 填写“第三阶段测试雨伞”，选择生活用品，地点填“图书馆”，联系方式填“演示微信 demo”。选择寻物并发布。
3. 应返回首页，出现成功提示，第一张卡片是新发布的信息，状态为“待寻找”。首次发布后总数为 6 条（若此前发布过，以实际数量为准）。
4. 按 F5 刷新同一个文件，新信息仍存在。
5. 再发布一条招领信息“第三阶段测试水杯”，确认类型为招领、状态为“待认领”。
6. 点击寻物／招领筛选，确认新增内容被正确分类。
7. 输入仅含空格的名称、地点或联系方式，确认不能发布；非空字段不会被清空。
8. 发布页暂离再返回，尚未提交的内容应保留；刷新未提交表单不保证保留草稿。
9. 如实际遇到保存失败，确认出现错误反馈且表单未清空，并记录浏览器版本、错误及处理过程。
